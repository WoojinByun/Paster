# Paster 설계 문서

작성일: 2026-10-22

## 1. 개요 / 목표

Paster 는 macOS 네이티브 클립보드 히스토리 앱이다. 사용자가 복사하는 텍스트 / 이미지 / 파일을 저장해 두고, 전역 단축키로 여는 패널에서 검색하고 붙여넣을 수 있다.

## 2. 비목표 (v1 범위 밖)

- Snippets
- Merging
- iCloud / 기기 간 동기화
- 파일 사본 보관 (경로만 저장)
- Space 키 Quick Look (검색 입력을 막으므로 사용하지 않음)
- Mac App Store / 샌드박스

## 3. 아키텍처 / 컴포넌트

### 3.1 전체 구조

- 메뉴바 상주 앱 (`LSUIElement`, Dock 아이콘 없음).
- 비샌드박스 (자동 붙여넣기에 손쉬운 사용 권한이 필요).
- SwiftUI + AppKit `NSPanel` (non-activating).
- SwiftPM 패키지: 로직은 `PasterCore` 라이브러리(테스트 대상), UI / 앱 진입점은 `Paster` 실행 타깃.
- 외부 의존성 3개
  - GRDB.swift (SQLite)
  - KeyboardShortcuts (sindresorhus, 전역 단축키 + 녹화 UI)
  - Sparkle 2 (SPM, 자동 업데이트)
- 로그인 시 실행: `SMAppService.mainApp`.
- 최소 macOS 15, Swift 6 strict concurrency.

### 3.2 컴포넌트

| 컴포넌트 | 역할 |
|---|---|
| AppDelegate | 시작 시 서비스 연결, 메뉴바 아이콘과 메뉴 (3.3절 참조) |
| ClipboardMonitor | `NSPasteboard.general.changeCount` 를 0.5초마다 폴링, 변경 시 ClipCapture 로 전달 |
| ClipCapture | pasteboard 를 ClipItem 으로 변환. `PasteboardReading` 프로토콜에만 의존 (가짜 pasteboard 로 테스트) |
| ClipStore | SQLite (GRDB) + FTS5. 저장 / 검색 / Pin / 삭제 / 중복 처리 |
| BlobStore | `blobs/<uuid>.png` 관리 |
| RetentionService | 만료 정리 |
| HotkeyService | KeyboardShortcuts 기반 전역 단축키 |
| PanelController | non-activating NSPanel. 열 때 직전 frontmost 앱을 기억 |
| PanelView (SwiftUI) | 검색창 / Clipboard \| Pinned 2칼럼 / 하단 미리보기 띠 |
| PasteService | pasteboard 쓰기 → 직전 앱 활성화 → CGEvent ⌘V. 일반 텍스트 모드 지원 |
| SettingsView | 타입별 보관 켬/끔·기간, 단축키, 제외 앱 목록, 로그인 시 실행, 자동 업데이트 확인 체크박스, 전체 삭제 (Clear All History) |
| SPUStandardUpdaterController | Sparkle 업데이트 담당 (13절 참조) |

## 5. 캡처 규칙

### 5.1 건너뛰는 경우 (ClipCapture)

- `org.nspasteboard.ConcealedType` / `TransientType` (및 AutoGeneratedType) 로 표시된 항목
- 제외 목록 앱 (복사 시점의 frontmost app bundle id 기준)
- Paster 자체 마커 타입 (`com.wjbyun.paster.internal`)
- 꺼진 타입 (캡처하지 않음)

### 5.2 타입 우선순위

파일 > 텍스트 (`public.utf8-plain-text` 가 비어있지 않음) > 이미지.

- Finder 에서 파일을 복사하면 아이콘 / 파일명이 같이 와도 파일로 처리한다.
- Word 텍스트에 그림 표현이 붙어 있어도 텍스트로 처리한다.
- 스크린샷 / 브라우저 이미지 복사는 이미지로 처리한다.

### 5.3 이미지 처리

- PNG 로 변환해 저장한다 (TIFF 는 거대하기 때문).
- 붙여넣을 때는 PNG + TIFF 둘 다 pasteboard 에 쓴다.
- PNG 결과가 100MB 를 초과하면 건너뛰고 로그를 남긴다.

### 5.4 중복 처리

같은 `content_hash` 를 다시 복사하면 새 행을 만들지 않고 `last_copied_at` 을 갱신하며 (맨 위로 올라옴), 출처 앱도 갱신한다.

## 6. 검색

- FTS5 `trigram` 토크나이저 사용 (한글 부분 문자열 검색).
- 1~2글자 검색은 `LIKE` 로 폴백.
- 검색 대상: `plain_text`, 파일명, 출처 앱 이름.
- 검색어는 Clipboard / Pinned 두 칼럼 모두에 필터로 적용된다.

## 7. 보관 정책 / 정리 스케줄

### 7.1 보관 정책

- 타입별 (텍스트 / 이미지 / 파일) 켬/끔 + 기간 (24시간 / 7일 / 1개월 / 3개월). 기본값은 모두 켬 · 3개월.
- 꺼진 타입의 기존 항목은 기간이 만료될 때까지 유지한다.
- 만료 조건: `pinned_at IS NULL AND last_copied_at < now - 기간`
- 만료 시 DB 행 + blob 을 삭제하고, 고아 blob 도 정리한다.
- Pin 항목은 만료되지 않는다.
- Pin 해제 시 `last_copied_at = now` 로 설정한다 (해제 즉시 삭제되는 것을 방지).
- 조회 시에도 만료 항목은 쿼리에서 제외한다 (정리 전이라도 화면에 나오지 않음).
- 설정의 전체 삭제 (Clear All History) 는 미고정 항목과 그 blob 만 삭제하고, Pinned 항목은 유지한다. 삭제 전에 확인 대화상자를 띄운다.

### 7.2 정리 시점

1. 다음 로컬 0시 타이머. 실행 후 다음 0시로 재설정한다.
2. 앱 실행 시.
3. 잠자기에서 깬 뒤, 마지막 정리 이후 날짜가 바뀌었으면.
4. 시간대 / 시계 변경 (`NSSystemClockDidChange`, `NSSystemTimeZoneDidChange`) 시 타이머를 재설정한다.

마지막 정리 날짜는 UserDefaults 에 기록한다. 앱은 로그인 시 실행으로 항상 상주한다.

## 8. 패널 UX / 키 조작

### 8.1 열기 / 닫기

- 기본 단축키 `⌃⌥⌘V` (설정에서 변경 가능).
- 메뉴바 아이콘을 클릭하면 메뉴가 열리고, 메뉴의 `Paster 열기` 로 패널을 연다.
- 마우스가 있는 화면의 중앙에 약 760×520 크기로 표시한다.
- 바깥 클릭 시 닫힌다.
- Esc: 검색어가 있으면 지우고, 없으면 닫는다.

### 8.2 레이아웃 목업

```
┌─────────────────────────────────┐
│ 🔍 _                              │
├── Clipboard ─────┬── Pinned ──────┤
│▸Image 1292x878  ⌘1│ 📌 배포 체크리스트│
│ eb2cafe2-cd82..  ⌘2│ 📌 서명         │
│ https://node..   ⌘3│ 📌 logo.png     │
├──────────────────┴──────────────┤
│ [미리보기]                        │
│ Finder · 13:31 · 1.2 MB           │
└─────────────────────────────────┘
```

### 8.3 포커스 이동

- 열면 검색창에 포커스가 간다.
- 검색창에서 ↓ → Clipboard 칼럼.
- 목록에서 ←/→ → 칼럼 전환 (Clipboard ↔ Pinned).
- 각 칼럼 (Clipboard / Pinned) 의 맨 위 항목에서 ↑ → 검색창.
- 왼쪽 칼럼에서 ←, 오른쪽 칼럼에서 → 는 아무 동작도 하지 않는다.
- 검색창 안에서 ←/→ 는 커서 이동만 한다.
- 목록 포커스 중 글자를 입력하면 검색창으로 돌아가 이어서 입력된다.
- 칼럼별 마지막 선택 위치를 기억한다.
- Clipboard 칼럼에는 미고정 항목만 표시한다 (중복 없음). Pinned 는 `pin_order` 순.

### 8.4 키 표

| 키 | 동작 |
|---|---|
| Enter / 더블클릭 | 붙여넣기 (서식 유지) |
| ⇧Enter | 일반 텍스트로 붙여넣기 |
| ⌘Enter | 복사만 |
| ⌘1~9 | 포커스 칼럼의 N번째 항목 붙여넣기 (검색창 포커스면 Clipboard 기준) |
| ⌘P | 고정 / 해제 (반대 칼럼으로 이동) |
| ⌥⌘↑ / ↓ | Pinned 순서 변경 |
| ⌘⌫ | 항목 삭제 |

### 8.5 행 표시

- 출처 앱 아이콘 + 제목
  - 텍스트: 첫 줄
  - 이미지: `Image: 1292x878 (1.2 MB)`
  - 파일: `파일: report.pdf 외 2개`
- 원본이 없는 파일은 ⚠ 로 표시한다.
- ⌘숫자 힌트는 포커스된 칼럼에만 표시한다.
- Pinned 가 비어 있으면 "⌘P로 고정" 안내를 표시한다.

### 8.6 하단 미리보기 띠

- 텍스트: 전문 (스크롤)
- 이미지: fit
- 파일: 전체 경로 + 존재 여부
- 메타 줄: `출처 앱 · 상대 시각 · 크기`

## 9. 붙여넣기 흐름 / 권한

### 9.1 흐름

1. 패널을 열 때 frontmost 앱을 기억한다.
2. Enter → pasteboard 에 쓴다. 자체 마커를 포함하므로 Monitor 가 캡처하지 않는다. 대신 PasteService 가 `last_copied_at` 을 갱신한다.
3. 패널을 닫고, 직전 앱 활성화가 완료된 뒤 CGEvent ⌘V 를 전송한다.

세부 규칙:

- 일반 텍스트 모드는 string 만 쓴다.
- 파일은 file URL 로 쓴다.
- 원본이 없는 파일은 붙여넣지 않고, 패널에 "원본 파일이 없습니다" 를 표시한다.

### 9.2 권한

- 첫 실행 시 `AXIsProcessTrustedWithOptions` 로 손쉬운 사용 권한을 요청한다.
- 권한이 없으면 Enter 시 복사만 하고, 시스템 설정의 손쉬운 사용 화면으로 가는 안내를 표시한다.
- 자체 인증서로 서명을 고정하여, 재빌드해도 권한이 유지되게 한다 (12절 참조).

## 10. 오류 처리

- DB 열기 실패 / 손상: `paster.sqlite.corrupt-<timestamp>` 로 보존하고 새 DB 를 만든다.
- 이미지 저장 실패 / 100MB 초과: 건너뛰고 로그를 남긴다.
- 로깅은 `os.Logger` (subsystem `com.wjbyun.Paster`). 클립보드 내용은 로그에 남기지 않는다.

## 11. 테스트

`swift test` (대상: PasterCore).

- ClipCapture (가짜 pasteboard): 우선순위, 민감 / 임시 항목 건너뜀, 제외 앱, 자체 마커
- ClipStore (임시 DB): 중복, Pin / 해제 시각 재설정, 정렬, trigram 검색 + 1~2글자 LIKE 폴백
- RetentionService (시계 주입): 타입별 만료, Pin 제외, blob 삭제, 다음 0시 계산
- 패널 포커스 로직: 순수 함수 `(PanelState, KeyEvent) → PanelState` 로 분리하여 키 표 그대로 테스트
- UI / 실제 붙여넣기: 수동 체크리스트 (텍스트 · 이미지 · 파일 복사 → 단축키 → TextEdit 에 붙여넣기, ⇧Enter, ⌘P, 만료)
- 자동 업데이트 수동 확인: 더 높은 버전의 테스트 release 를 올린 뒤 `업데이트 확인…` 으로 감지 · 설치 · 재실행 확인

## 12. 빌드 / 설치 / 서명

이 Mac 에는 코드 서명 인증서가 없다. ad-hoc 서명은 재빌드마다 손쉬운 사용 권한을 다시 요청하므로, 자체 서명 인증서를 사용한다.

- `make cert` (최초 1회): 자체 서명 코드서명 인증서 "Paster Local Signing" 을 로그인 키체인에 생성
- `make app`: `swift build -c release` → `build/Paster.app` 조립 (Info.plist 의 `LSUIElement`, 번들 ID) → 해당 인증서로 codesign
- `make install`: `/Applications` 로 복사 (SMAppService 의 안정적 동작을 위해)
- `make test`: `swift test`
- `make sparkle-keys`: Sparkle 의 `generate_keys` 를 1회 실행 (13절 참조)
- `make release VERSION=x.y.z`: 릴리스 빌드 · 서명 · appcast 생성 · GitHub Release 업로드 (13절 참조)

## 13. 자동 업데이트 (Sparkle)

- 앱에 `SPUStandardUpdaterController` 를 둔다. 메뉴의 `업데이트 확인…` 은 `checkForUpdates` 를 호출한다. 업데이트가 발견되면 Sparkle 표준 창이 릴리스 노트를 보여주고 설치 후 재실행을 제안한다.
- SettingsView 에 "자동으로 업데이트 확인" 체크박스를 두고 `updater.automaticallyChecksForUpdates` 에 바인딩한다. 기본값 ON, Sparkle 기본 확인 주기는 매일.
- Info.plist
  - `SUFeedURL` = `https://github.com/WoojinByun/Paster/releases/latest/download/appcast.xml`
  - `SUPublicEDKey` (EdDSA 공개 키)
  - `SUEnableAutomaticChecks` 는 체크박스에 맡기고 따로 지정하지 않는다.
- 키: `make sparkle-keys` 가 Sparkle 의 `generate_keys` 를 1회 실행한다. EdDSA 개인 키는 로그인 키체인에 보관하며 절대 커밋하지 않는다. Info.plist 에는 공개 키만 넣는다.
- 버전: `CFBundleShortVersionString` = `VERSION=x.y.z` 의 semver. `CFBundleVersion` = 단조 증가 빌드 번호 (`git rev-list --count HEAD`).
- `make release VERSION=x.y.z` 순서
  1. release 빌드
  2. `Paster.app` 조립
  3. "Paster Local Signing" 으로 codesign
  4. `ditto -c -k --keepParent` 로 zip
  5. `generate_appcast` (키체인의 EdDSA 키로 서명)
  6. `gh release create vX.Y.Z` 로 zip 과 `appcast.xml` 업로드. appcast 의 다운로드 URL 은 해당 release 의 zip asset 을 가리킨다.
- 서명 연속성: Sparkle 은 업데이트가 같은 identity 로 서명되었을 것을 요구하고, 같은 자체 서명 인증서가 손쉬운 사용 (TCC) 권한도 유지시켜 준다. 따라서 README 에서 "Paster Local Signing" 인증서와 Sparkle 개인 키를 백업하라고 안내한다. 둘 중 하나를 잃으면 업데이트가 깨지거나 권한이 초기화된다.
- 제한: 앱은 notarize 되지 않는다. Releases 에서 새로 내려받은 사용자는 Gatekeeper 를 만나게 된다 (우클릭 → 열기, 또는 `xattr -dr com.apple.quarantine`). Sparkle 로 전달되는 업데이트는 영향을 받지 않는다. 개인 용도로 허용한다.

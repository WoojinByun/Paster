# Paster 설계 문서

작성일: 2026-10-22

## 1. 개요 / 목표

Paster 는 macOS 네이티브 클립보드 히스토리 앱이다. 사용자가 복사하는 텍스트 / 이미지 / 파일을 저장해 두고, 전역 단축키로 여는 패널에서 검색하고 붙여넣을 수 있다.

## 2. 비목표 (v1 범위 밖)

- Snippets
- Merging
- iCloud / 기기 간 동기화
- 파일 사본 보관 (경로만 저장)
- Space 키 Quick Look (검색 입력을 막으므로 사용하지 않음)
- Mac App Store / 샌드박스

## 3. 아키텍처 / 컴포넌트

### 3.1 전체 구조

- 메뉴바 상주 앱 (`LSUIElement`, Dock 아이콘 없음).
- 비샌드박스 (자동 붙여넣기에 손쉬운 사용 권한이 필요).
- SwiftUI + AppKit `NSPanel` (non-activating).
- SwiftPM 패키지: 로직은 `PasterCore` 라이브러리(테스트 대상), UI / 앱 진입점은 `Paster` 실행 타깃.
- 외부 의존성 3개
  - GRDB.swift (SQLite)
  - KeyboardShortcuts (sindresorhus, 전역 단축키 + 녹화 UI)
  - Sparkle 2 (SPM, 자동 업데이트)
- 로그인 시 실행: `SMAppService.mainApp`. 기본값은 꺼짐이며 설정에서 켠다. 0시 정리가 돌려면 앱이 떠 있어야 하므로 켜 두기를 권장한다.
- 단일 인스턴스: 데이터 디렉터리의 `paster.lock` 에 `flock` 을 잡는다. 이미 다른 Paster 가 실행 중이면 저장소를 열기 전에 "Paster가 이미 실행 중입니다" 를 알리고 종료한다 (종료 · 크래시 시 커널이 잠금을 푼다).
- 대상 아키텍처: arm64 (Apple Silicon) 전용. Intel Mac 은 지원하지 않는다.
- 최소 macOS 15, Swift 6 strict concurrency.

### 3.2 컴포넌트

| 컴포넌트 | 역할 |

### 3.3 메뉴바 메뉴

```
Paster 열기                                (패널 토글)
Paster <CFBundleShortVersionString> (<CFBundleVersion>)   (비활성, 회색)
────────────
설정…  ⌘,
────────────
업데이트 확인…
────────────
종료  ⌘Q
```

- 예약 확인에서 업데이트를 찾았는데 Sparkle 이 창을 바로 띄우지 않은 경우 (메뉴바 앱이라 창이 뒤에 묻힌다), 메뉴바 아이콘 오른쪽 위에 점 배지를 붙이고 메뉴 항목을 `업데이트 설치 가능…` 으로 바꾼다. 사용자가 업데이트를 보거나 세션이 끝나면 원래대로 돌아온다 (13절 참조).
- 앱이 막 실행돼 초점이 있을 때 찾은 업데이트는 Sparkle 이 직접 창으로 보여 준다.

## 4. 데이터 모델 / 저장

- 저장 위치: `~/Library/Application Support/Paster/`
  - `paster.sqlite`
  - `blobs/<uuid>.png`
- 설정: `UserDefaults`
- 번들 ID: `com.wjbyun.Paster`
- SQLite `secure_delete` 를 켠다. 삭제한 행의 내용이 DB 파일의 빈 페이지에 남지 않게 하기 위해서다. SQLite 3.44 이상이면 FTS5 인덱스(`clip_fts`)의 `secure-delete` 옵션도 켠다 (실행할 때마다 확인).
- 손상된 DB 를 격리하면 `blobs/` 를 먼저 같은 접미사의 `blobs.corrupt-<timestamp>` 로 옮긴 뒤 DB 파일(`paster.sqlite.corrupt-<timestamp>`, 10절)을 옮기고 빈 `blobs/` 를 새로 만든다. 따라서 격리본이 참조하던 blob 은 새 DB 의 고아 blob 정리가 지우지 않는다. 이름이 겹치면 DB 와 blob 디렉터리 모두 `-1`, `-2` … 를 붙인다.

### 테이블 `clip_items`

| 칼럼 | 설명 |
|---|---|
| `id` | 기본 키 |
| `kind` | `text` / `image` / `files` |
| `plain_text` | 텍스트 본문. 파일이면 파일명 목록 |
| `rtf` | BLOB, 있을 때만 |
| `html` | BLOB, 있을 때만 |
| `image_blob` | 이미지 blob 참조 |
| `image_width` | 이미지 너비 |
| `image_height` | 이미지 높이 |
| `byte_size` | 크기 |
| `file_paths` | JSON 배열 |
| `source_bundle_id` | 출처 앱 bundle id |
| `source_app_name` | 출처 앱 이름 |
| `content_hash` | UNIQUE, sha256 |
| `created_at` | 최초 생성 시각 |
| `last_copied_at` | 정렬 · 만료 기준 |
| `pinned_at` | NULL 이면 미고정 |
| `pin_order` | Pinned 칼럼 정렬 순서 |

## 5. 캡처 규칙

### 5.1 건너뛰는 경우 (ClipCapture)

- `org.nspasteboard.ConcealedType` / `TransientType` (및 AutoGeneratedType) 로 표시된 항목
- 제외 목록 앱. 직전 폴링 이후 제외 앱이 한 번이라도 frontmost 였으면 그 복사는 건너뛴다 (폴링 사이에 앱을 전환해도 제외 앱의 복사가 다른 앱 출처로 저장되지 않게 한다). 이때 내용은 읽지도 않는다.
- Paster 자체 마커 타입 (`com.wjbyun.paster.internal`)
- 꺼진 타입 (캡처하지 않음)
- 텍스트 항목의 크기 (plain text 의 UTF-8 바이트 + RTF + HTML 바이트 합계) 가 20 MB (20 × 1024 × 1024 바이트) 를 넘는 항목 (캡처하지 않음, 크기만 로그로 남김)

### 5.2 타입 우선순위

파일 > 텍스트 (`public.utf8-plain-text` 가 비어있지 않음) > 이미지.

- Finder 에서 파일을 복사하면 아이콘 / 파일명이 같이 와도 파일로 처리한다.
- Word 텍스트에 그림 표현이 붙어 있어도 텍스트로 처리한다.
- 스크린샷 / 브라우저 이미지 복사는 이미지로 처리한다.

### 5.3 이미지 처리

- PNG 로 변환해 저장한다 (TIFF 는 거대하기 때문).
- 붙여넣을 때는 PNG + TIFF 둘 다 pasteboard 에 쓴다.
- PNG 결과가 100MB 를 초과하면 건너뛰고 로그를 남긴다.
- 텍스트는 plain text(UTF-8) + RTF + HTML 합계가 20 MB 를 초과하면 건너뛴다 (5.1절).

### 5.4 중복 처리

같은 `content_hash` 를 다시 복사하면 새 행을 만들지 않고 `last_copied_at` 을 갱신하며 (맨 위로 올라옴), 출처 앱도 갱신한다.

## 6. 검색

- FTS5 `trigram` 토크나이저 사용 (한글 부분 문자열 검색).
- 1~2글자 검색은 `LIKE` 로 폴백.
- 검색 대상: `plain_text`, 파일명, 출처 앱 이름.
- 검색어는 Clipboard / Pinned 두 칼럼 모두에 필터로 적용된다.

## 7. 보관 정책 / 정리 스케줄

### 7.1 보관 정책

- 타입별 (텍스트 / 이미지 / 파일) 켬/끔 + 기간 (24시간 / 7일 / 1개월 / 3개월). 기본값은 모두 켬 · 3개월.
- 꺼진 타입의 기존 항목은 기간이 만료될 때까지 유지한다.
- 만료 조건: `pinned_at IS NULL AND last_copied_at < now - 기간`
- 만료 시 DB 행 + blob 을 삭제하고, 고아 blob 도 정리한다.
- Pin 항목은 만료되지 않는다.
- Pin 해제 시 `last_copied_at = now` 로 설정한다 (해제 즉시 삭제되는 것을 방지).
- 조회 시에도 만료 항목은 쿼리에서 제외한다 (정리 전이라도 화면에 나오지 않음).
- 설정의 전체 삭제 (Clear All History) 는 미고정 항목과 그 blob 만 삭제하고, Pinned 항목은 유지한다. 삭제 전에 확인 대화상자를 띄운다.

### 7.2 정리 시점

1. 다음 로컬 0시 타이머. 실행 후 다음 0시로 재설정한다.
2. 앱 실행 시.
3. 잠자기에서 깬 뒤, 마지막 정리 이후 날짜가 바뀌었으면.
4. 시간대 / 시계 변경 (`NSSystemClockDidChange`, `NSSystemTimeZoneDidChange`) 시 타이머를 재설정한다.

마지막 정리 날짜는 UserDefaults 에 기록한다. 이 스케줄은 앱이 계속 실행 중이라고 가정한다. 로그인 시 실행은 기본 꺼짐이므로, 0시 정리를 받으려면 사용자가 설정에서 켜는 것을 권장한다 (꺼 두면 앱을 실행할 때와 깨어날 때 정리된다).

## 8. 패널 UX / 키 조작

### 8.1 열기 / 닫기

- 기본 단축키 `⌃⌥⌘V` (설정에서 변경 가능).
- 메뉴바 아이콘을 클릭하면 메뉴가 열리고, 메뉴의 `Paster 열기` 로 패널을 연다.
- 마우스가 있는 화면의 중앙에 약 760×520 크기로 표시한다.
- 바깥 클릭 시 닫힌다.
- Esc: 검색어가 있으면 지우고, 없으면 닫는다.

### 8.2 레이아웃 목업

```
┌─────────────────────────────────┐
│ 🔍 _                              │
├── Clipboard ─────┬── Pinned ──────┤
│▸Image 1292x878  ⌘1│ 📌 배포 체크리스트│
│ eb2cafe2-cd82..  ⌘2│ 📌 서명         │
│ https://node..   ⌘3│ 📌 logo.png     │
├──────────────────┴──────────────┤
│ [미리보기]                        │
│ Finder · 13:31 · 1.2 MB           │
└─────────────────────────────────┘
```

### 8.3 포커스 이동

- 열면 검색창에 포커스가 간다.
- 검색창에서 ↓ → Clipboard 칼럼. Clipboard 가 비어 있으면 Pinned 칼럼 (둘 다 비어 있으면 그대로).
- 목록에서 ←/→ → 칼럼 전환 (Clipboard ↔ Pinned).
- 각 칼럼 (Clipboard / Pinned) 의 맨 위 항목에서 ↑ → 검색창.
- 왼쪽 칼럼에서 ←, 오른쪽 칼럼에서 → 는 아무 동작도 하지 않는다.
- 검색창 안에서 ←/→ 는 커서 이동만 한다.
- 목록 포커스 중 글자를 입력하면 검색창으로 돌아가 이어서 입력된다.
- 목록에서 클릭하면 선택만 되고, 더블클릭하면 붙여넣는다.
- IME 조합 규칙: 검색창에 조합 중인 글자 (marked text) 가 있는 동안에는 Enter · Esc · 화살표 등 모든 키를 검색창 (field editor) 에 맡기고 패널 동작은 일어나지 않는다. 조합이 끝난 뒤 다시 누르면 키 표대로 동작한다.
- 칼럼별 마지막 선택 위치를 기억한다.
- Clipboard 칼럼에는 미고정 항목만 표시한다 (중복 없음). Pinned 는 `pin_order` 순.

### 8.4 키 표

| 키 | 동작 |
|---|---|
| Enter / 더블클릭 | 붙여넣기 (서식 유지) |
| ⇧Enter | 일반 텍스트로 붙여넣기 |
| ⌘Enter | 복사만 |
| ⌘1~9 | 포커스 칼럼의 N번째 항목 붙여넣기 (검색창 포커스면 Clipboard 기준) |
| ⌘P | 고정 / 해제 (반대 칼럼으로 이동). 목록 포커스에서만 |
| ⌥⌘↑ / ↓ | Pinned 순서 변경. Pinned 목록 포커스에서만, 검색어가 있는 동안에는 비활성 |
| ⌘⌫ | 항목 삭제. 목록 포커스에서만 (검색창에서는 글자 삭제) |
| ⌘C | 목록 포커스에서는 선택 항목 복사 (⌘Enter 와 같은 경로). 검색창에서는 글자 복사 |
| ⌘X / ⌘V / ⌘A / ⌘Z | 검색창 편집. 메인 메뉴가 없는 앱이라 패널이 직접 검색창으로 보낸다. 목록 포커스에서 누르면 검색창으로 돌아가 적용 |

### 8.5 행 표시

- 출처 앱 아이콘 + 제목
  - 텍스트: 첫 줄
  - 이미지: `Image: 1292x878 (1.2 MB)`
  - 파일: `파일: report.pdf 외 2개`
- 원본이 없는 파일은 ⚠ 로 표시한다.
- ⌘숫자 힌트는 포커스된 칼럼에만 표시한다.
- Pinned 가 비어 있으면 "⌘P로 고정" 안내를 표시한다.

### 8.6 하단 미리보기 띠

- 텍스트: 전문 (스크롤)
- 이미지: fit
- 파일: 전체 경로 + 존재 여부
- 메타 줄: `출처 앱 · 상대 시각 · 크기`

## 9. 붙여넣기 흐름 / 권한

### 9.1 흐름

1. 패널을 열 때 frontmost 앱을 기억한다.
2. Enter → pasteboard 에 쓴다. 자체 마커를 포함하므로 Monitor 가 캡처하지 않는다. 대신 PasteService 가 `last_copied_at` 을 갱신한다.
3. 패널을 닫고, 직전 앱 활성화가 완료된 뒤 CGEvent ⌘V 를 전송한다.

세부 규칙:

- 일반 텍스트 모드는 string 만 쓴다.
- 파일은 file URL 로 쓴다.
- 원본이 없는 파일은 붙여넣지 않고, 패널에 "원본 파일이 없습니다" 를 표시한다.

### 9.2 권한

- 첫 실행 시 `AXIsProcessTrustedWithOptions` 로 손쉬운 사용 권한을 요청한다.
- 권한이 없으면 Enter 시 복사만 하고, 시스템 설정의 손쉬운 사용 화면으로 가는 안내를 표시한다.
- 자체 인증서로 서명을 고정하여, 재빌드해도 권한이 유지되게 한다 (12절 참조).

## 10. 오류 처리

- DB 손상 (SQLITE_NOTADB / SQLITE_CORRUPT 또는 quick_check 실패): `blobs.corrupt-<timestamp>` 와 `paster.sqlite.corrupt-<timestamp>` 로 보존하고 빈 `blobs/` 와 새 DB 를 만든다. 그 밖의 열기 실패 (BUSY · 권한 등) 는 DB 를 건드리지 않고 오류로 끝낸다.
- 잠금 파일(`paster.lock`)을 만들거나 잠글 수 없음: "잠금 파일을 만들 수 없습니다." 와 오류 설명을 알리고 종료한다.
- 이미지 저장 실패 / 100MB 초과: 건너뛰고 로그를 남긴다.
- 다른 인스턴스가 실행 중: 저장소를 열기 전에 "Paster가 이미 실행 중입니다" 를 알리고 종료한다 (3.1절).
- 로깅은 `os.Logger` (subsystem `com.wjbyun.Paster`). 클립보드 내용은 로그에 남기지 않는다.

## 11. 테스트

`swift test` (대상: PasterCore).

- ClipCapture (가짜 pasteboard): 우선순위, 민감 / 임시 항목 건너뜀, 제외 앱, 자체 마커

## 12. 빌드 / 설치 / 서명

이 Mac 에는 코드 서명 인증서가 없다. ad-hoc 서명은 재빌드마다 손쉬운 사용 권한을 다시 요청하므로, 자체 서명 인증서를 사용한다.

- `make cert` (최초 1회): 자체 서명 코드서명 인증서 "Paster Local Signing" 을 로그인 키체인에 생성
- `make app`: `swift build -c release` → `build/Paster.app` 조립 (Info.plist 의 `LSUIElement`, 번들 ID) → 해당 인증서로 codesign
- `make run`: debug 빌드를 같은 인증서로 서명해 `build/debug/Paster.app` 으로 실행 (개발용)
- `make icon`: `Resources/AppIcon.svg` → `Resources/AppIcon.icns`
- 대상은 arm64 전용이다. Intel Mac 은 지원하지 않는다.
- 개발 빌드 (debug 구성, 또는 `VERSION=0.0.0`) 는 Info.plist 에 `SUFeedURL` 이 없어 업데이트를 받지 않는다. 개발 빌드는 릴리스와 같은 번들 ID · 데이터를 쓰는데 빌드 번호가 더 낮아, 피드가 있으면 Sparkle 이 정식 릴리스로 개발 빌드를 덮어쓸 수 있기 때문이다. 피드가 없으면 앱은 첫 실행 때 자동 확인을 켜지 않고, 설정의 "자동으로 업데이트 확인" 토글을 비활성화하고 "개발용 빌드: 업데이트 피드가 없습니다" 를 보여 준다. 메뉴의 `업데이트 확인…` 은 그대로 켜 두며, 누르면 Sparkle 설정 오류를 보여 주는 것이 정상이다. 업데이트를 받는 앱은 Releases 의 zip 이나 `VERSION=x.y.z` 를 지정한 빌드로 설치한다.
- `make install`: `/Applications` 로 복사 (SMAppService 의 안정적 동작을 위해)
- `make test`: `swift test`
- `make sparkle-keys`: Sparkle 의 `generate_keys` 를 1회 실행 (13절 참조)
- `make release VERSION=x.y.z`: 릴리스 빌드 · 서명 · appcast 생성 · GitHub Release 업로드 (13절 참조)

## 13. 자동 업데이트 (Sparkle)

- 앱에 `SPUStandardUpdaterController` 를 둔다. 메뉴의 `업데이트 확인…` 은 `checkForUpdates` 를 호출한다. 업데이트가 발견되면 Sparkle 표준 창이 릴리스 노트를 보여주고 설치 후 재실행을 제안한다.
- SettingsView 에 "자동으로 업데이트 확인" 체크박스를 두고 `updater.automaticallyChecksForUpdates` 에 바인딩한다. 기본값 ON, Sparkle 기본 확인 주기는 매일. 피드가 없는 개발 빌드에서는 기본값을 켜지 않고 체크박스를 비활성화한다 (12절).
- Info.plist
  - `SUFeedURL` = `https://github.com/WoojinByun/Paster/releases/latest/download/appcast.xml` (정식 `VERSION` 으로 만든 빌드만. 개발 빌드는 12절)
  - `SUPublicEDKey` (EdDSA 공개 키)
  - `SUEnableAutomaticChecks` 는 정식 빌드에서는 체크박스에 맡기고 따로 지정하지 않는다. 개발 빌드는 `false` 로 둔다.
- 키: `make sparkle-keys` 가 Sparkle 의 `generate_keys` 를 1회 실행한다. EdDSA 개인 키는 로그인 키체인에 보관하며 절대 커밋하지 않는다. Info.plist 에는 공개 키만 넣는다.
- 버전: `CFBundleShortVersionString` = `VERSION=x.y.z` 의 semver. `CFBundleVersion` = 단조 증가 빌드 번호 (`git rev-list --count HEAD`).
  - 빌드 번호가 커밋 수에 의존하므로 main 에는 merge commit 이나 fast-forward 로만 합치고 squash merge 는 하지 않는다. squash 하면 번호가 되돌아가 이미 설치된 앱이 새 릴리스를 업데이트로 인식하지 못한다.
- 예약 확인에서 업데이트를 찾으면 `SPUStandardUserDriverDelegate` 의 gentle reminder 로 메뉴바 아이콘에 점 배지를 붙인다 (3.3절).
- `make release VERSION=x.y.z` 순서
  1. release 빌드
  2. `Paster.app` 조립
  3. "Paster Local Signing" 으로 codesign
  4. `ditto -c -k --keepParent` 로 zip
  5. `generate_appcast` (키체인의 EdDSA 키로 서명)
  6. `gh release create vX.Y.Z` 로 zip 과 `appcast.xml` 업로드. appcast 의 다운로드 URL 은 해당 release 의 zip asset 을 가리킨다.
- 서명 연속성: Sparkle 은 업데이트가 같은 identity 로 서명되었을 것을 요구하고, 같은 자체 서명 인증서가 손쉬운 사용 (TCC) 권한도 유지시켜 준다. 따라서 README 에서 "Paster Local Signing" 인증서와 Sparkle 개인 키를 백업하라고 안내한다. 둘 중 하나를 잃으면 업데이트가 깨지거나 권한이 초기화된다.
- 제한: 앱은 notarize 되지 않는다. Releases 에서 새로 내려받은 사용자는 Gatekeeper 를 만나게 된다 (우클릭 → 열기, 또는 `xattr -dr com.apple.quarantine`). Sparkle 로 전달되는 업데이트는 영향을 받지 않는다. 개인 용도로 허용한다.

## 15. 리뷰 반영 (2026-10-23)

최종 리뷰 후 구현에 맞춰 이 문서를 고쳤다.

- 키 조작 (8.3 / 8.4절): Clipboard 가 비면 검색창의 ↓ 는 Pinned 로 간다. ⌘P · ⌥⌘↑/↓ · ⌘⌫ 는 목록 포커스에서만 동작하고, 검색창에서 ⌘⌫ 는 글자 삭제다. ⌥⌘↑/↓ 는 Pinned 에서만, 검색 중에는 비활성이다. 목록 포커스의 ⌘C 는 ⌘Enter 와 같이 항목을 복사한다. ⌘X/V/A/Z 는 검색창으로 전달한다.
- IME 조합 규칙 (8.3절): 조합 중에는 모든 키를 검색창에 맡긴다.
- 단일 인스턴스 (3.1 / 10절): `paster.lock` 으로 중복 실행을 막고 "Paster가 이미 실행 중입니다" 를 알린다.
- 출처 앱 판정 (5.1절): 직전 폴링 이후 제외 앱이 frontmost 였으면 그 복사를 건너뛴다.
- 텍스트 20 MB 상한 (5.1 / 5.3절).
- 저장소 (4절): SQLite `secure_delete`, 격리된 손상 DB 가 참조하는 blob 은 고아 정리에서 보존.
- 메뉴바 업데이트 배지 (3.3 / 13절).
- 개발 빌드는 Sparkle 피드를 끈다 (12 / 13절). 이유와 `업데이트 확인…` 동작을 적었다.
- 빌드 번호와 merge 전략 (13절): squash merge 금지.
- arm64 전용 (3.1 / 12절).
- 로그인 시 실행은 기본 꺼짐이며 켜기를 권장한다 (3.1 / 7.2절). `make run` · `make icon` 을 12절에 추가했다.
- FTS `secure-delete` (4절): 마이그레이션이 아니라 실행할 때마다 SQLite 버전을 확인해 켠다. 3.44 미만에서 처음 실행했어도 OS 업데이트 뒤 켜진다.
- 손상 DB 격리 순서 (4 / 10절): `blobs/` 를 먼저 옮기고 DB 파일을 옮긴다. DB 파일을 옮기다 실패하면 `blobs/` 를 되돌리고 오류로 끝낸다.
- 텍스트 20 MB 상한은 plain text + RTF + HTML 합계 기준이다 (5.1 / 5.3절).
- 잠금 파일 오류 (10절): 이미 실행 중인 경우와 따로 "잠금 파일을 만들 수 없습니다." 를 알린다.
- 개발 빌드 (12 / 13절): 피드가 없어 업데이트를 받지 않으며 설정의 자동 확인 토글을 비활성화한다.
- 패널 행 제목: 목록 행은 앞 `ClipStore.listTextLimit` 글자만 들고 있어, 첫 비어 있지 않은 줄이 그보다 뒤에 있으면 "(공백)" 으로 보인다.

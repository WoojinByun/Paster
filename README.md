# Paster

macOS 메뉴바에 상주하는 클립보드 히스토리 앱. 복사한 텍스트 / 이미지 / 파일을 저장해 두고, 전역 단축키로 여는 패널에서 검색해 붙여넣습니다.

릴리스는 [GitHub Releases](https://github.com/WoojinByun/Paster/releases) 페이지에서 받을 수 있습니다.

## 주요 기능

- 텍스트 / 이미지 / 파일 복사 히스토리
- 검색 (한글 부분 문자열 검색 지원)
- Clipboard | Pinned 2칼럼 패널
- 자동 붙여넣기, 일반 텍스트로 붙여넣기
- 타입별 보관 기간 설정 + 매일 자동 정리
- 제외할 앱 지정, 비밀번호 관리자 등의 숨김(concealed) 항목은 저장하지 않음
- 로그인 시 실행 옵션 (기본 꺼짐, 설정에서 켭니다)
- Sparkle 자동 업데이트

## 요구 사항

- macOS 15 이상
- Apple Silicon (arm64) 전용입니다. Intel Mac 은 지원하지 않습니다.

## 설치 (사용자용)

1. [GitHub Releases 최신 버전](https://github.com/WoojinByun/Paster/releases/latest)에서 `Paster-x.y.z.zip` 을 내려받습니다.
2. 압축을 풀고 `Paster.app` 을 `/Applications` 로 옮깁니다.

### Gatekeeper

앱이 notarize 되어 있지 않아 첫 실행이 차단됩니다. macOS 15 이상에서는 우클릭 → 열기로 우회할 수 없습니다. 아래 둘 중 하나를 사용하세요. (한 번만 하면 됩니다.)

1. 시스템 설정 → 개인정보 보호 및 보안 → 아래로 스크롤 → "그래도 열기"
2. 터미널에서:

   ```sh
   xattr -dr com.apple.quarantine /Applications/Paster.app
   ```

### 손쉬운 사용 권한

첫 실행 시 권한 요청 창이 한 번 뜹니다. 시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용 에서 Paster 를 허용해 주세요.

자동 붙여넣기는 직전에 쓰던 앱으로 ⌘V 를 보내는 방식이라 이 권한이 필요합니다. 권한이 없으면 Enter 를 눌러도 클립보드에 복사만 되고, 패널 하단에 안내와 "시스템 설정 열기" 버튼이 표시됩니다 (이때는 직접 ⌘V 로 붙여넣으세요).

### 업데이트

업데이트는 Sparkle 이 주기적으로 자동 확인합니다. 설정의 "자동으로 업데이트 확인" 으로 끌 수 있고, 메뉴바 아이콘 메뉴의 `업데이트 확인…` 으로 직접 확인할 수도 있습니다.

새 업데이트가 있으면 메뉴바 아이콘에 점 배지가 붙고 메뉴 항목이 `업데이트 설치 가능…` 으로 바뀝니다. 업데이트 후에도 손쉬운 사용 권한은 유지됩니다.

## 사용법

기본 단축키는 `⌃⌥⌘V` 입니다 (설정에서 변경 가능). 메뉴바 아이콘 → `Paster 열기` 로도 열 수 있습니다. 같은 단축키로 닫을 수 있고, 패널 바깥을 클릭해도 닫힙니다.

Paster 는 한 번에 하나만 실행됩니다. 이미 실행 중일 때 다시 시작하면 "Paster가 이미 실행 중입니다" 안내가 뜨고 새 인스턴스는 종료됩니다.

```
┌─────────────────────────────────┐
│ 🔍 _                              │
├── Clipboard ─────┬── Pinned ──────┤
│▸Image 1292x878  ⌘1│ 📌 배포 체크리스트│
│ eb2cafe2-cd82..  ⌘2│ 📌 서명         │
│ https://node..   ⌘3│ 📌 logo.png     │
├──────────────────┴──────────────┤
│ [미리보기]                        │
│ Finder · 13:31 · 1.2 MB           │
└─────────────────────────────────┘
```

### 포커스 이동

- 열면 검색창에 포커스가 갑니다.
- 검색창에서 ↓ → Clipboard 칼럼 (비어 있으면 Pinned).
- 목록에서 ←/→ → 칼럼 전환 (Clipboard ↔ Pinned).
- 각 칼럼의 맨 위 항목에서 ↑ → 검색창.
- 왼쪽 칼럼에서 ←, 오른쪽 칼럼에서 → 는 아무 동작도 하지 않습니다.
- 검색창 안에서 ←/→ 는 커서 이동만 합니다.
- 목록 포커스 중 글자를 입력하면 검색창으로 돌아가 이어서 입력됩니다.
- 목록 포커스에서 클릭하면 선택만 되고, 더블클릭하면 붙여넣습니다.
- 칼럼별 마지막 선택 위치를 기억합니다.
- Clipboard 칼럼에는 고정하지 않은 항목만 표시됩니다 (Pinned 와 중복 없음).

### 키 표

| 키 | 동작 |
|---|---|
| Enter / 더블클릭 | 붙여넣기 (서식 유지) |
| ⇧Enter | 일반 텍스트로 붙여넣기 |
| ⌘Enter | 복사만 |
| ⌘1~9 | 포커스 칼럼의 N번째 항목 붙여넣기 (검색창 포커스면 Clipboard 기준) |
| ⌘P | 고정 / 해제 (반대 칼럼으로 이동). 목록 포커스에서만 |
| ⌥⌘↑ / ↓ | Pinned 순서 변경. Pinned 목록 포커스에서만, 검색어가 있는 동안에는 비활성 |
| ⌘⌫ | 선택 항목 삭제. 목록 포커스에서만 (검색창에서는 글자 삭제) |
| ⌘C | 목록 포커스에서는 선택 항목 복사 (⌘Enter 와 같음) |
| ⌘X / ⌘V / ⌘A / ⌘Z | 검색창 편집 (목록 포커스에서 누르면 검색창으로 돌아가 적용) |
| ⌘, | 패널을 닫고 설정 창 열기 |
| Esc | 검색어가 있으면 지우고, 없으면 패널 닫기 |
| ↓ / ↑ / ← / → | 포커스 이동 (위 규칙 참조) |
| PageUp (fn+↑) / PageDown (fn+↓) | 칼럼에 한 화면에 보이는 행 수만큼 위 / 아래로 이동 (맨 위 · 맨 아래에서 멈춤) |
| Home (fn+←) / End (fn+→) | 칼럼의 첫 항목 / 마지막 항목 선택 |

PageUp / PageDown / Home / End 는 수정 키 없이 눌렀을 때만 동작하고, 칼럼을 넘나들거나 검색창으로 돌아가지 않습니다. 검색창에서 누르면 ↓ 처럼 Clipboard 칼럼 (비어 있으면 Pinned) 으로 들어간 뒤 적용됩니다.

한글 등 IME 로 글자를 조합하는 중에는 Enter, Esc, 화살표가 조합 중인 글자를 확정하는 데만 쓰이고 패널 동작은 일어나지 않습니다. 조합이 끝난 뒤 다시 누르면 위 표대로 동작합니다.

## 설정

메뉴바 아이콘 → `설정…` 에서 엽니다. 메뉴바 메뉴나 패널이 열려 있을 때 `⌘,` 를 눌러도 열립니다.

- 보관 기간: 텍스트 / 이미지 / 파일 타입별 켬/끔 + 24시간 / 7일 / 1개월 / 3개월 (기본: 모두 켬, 3개월). 끈 타입은 새로 저장하지 않으며 기존 항목은 기간이 끝날 때까지 유지됩니다. 고정한 항목은 만료되지 않습니다.
- 단축키: 패널 열기 단축키 변경 (기본 `⌃⌥⌘V`)
- 제외할 앱: 추가 / 제거. 이 앱에서 복사한 내용은 저장하지 않습니다.
- 로그인 시 실행: 기본값은 꺼짐입니다. 만료 항목 정리는 앱이 실행 중일 때만 돌므로 켜 두기를 권장합니다. 켜면 macOS 가 승인을 요구할 수 있습니다. 설정에 안내가 뜨면 시스템 설정 → 일반 → 로그인 항목에서 Paster 를 허용해 주세요.
- 자동으로 업데이트 확인
- Clear All History…: 고정하지 않은 항목만 삭제하며 Pinned 는 유지합니다 (확인 대화상자 표시, 되돌릴 수 없음)

만료 항목 정리는 앱 실행 시, 매일 0시, 잠자기에서 깬 뒤(날짜가 바뀐 경우)에 자동으로 실행됩니다.

## 개인정보

- 모든 데이터는 `~/Library/Application Support/Paster/` 에만 저장됩니다.
- Sparkle 의 업데이트 확인(GitHub) 외에는 어디로도 데이터를 보내지 않습니다.
- 비밀번호 관리자 등이 concealed / transient 로 표시한 항목과 제외한 앱에서 복사한 내용은 내용을 읽지도 저장하지도 않습니다.
- 클립보드 내용은 로그에 남기지 않습니다.
- 데이터 삭제: 설정의 Clear All History (Pinned 는 유지), 또는 Paster 를 종료한 뒤 위 폴더를 삭제하면 Pinned 를 포함한 모든 데이터가 지워집니다.

## 소스에서 빌드 (개발자용)

Xcode 16+ / Swift 6 필요.

```sh
make cert      # 최초 1회: 자체 서명 인증서 "Paster Local Signing" 생성 (로그인 암호 입력)
make run       # debug 빌드를 build/debug/Paster.app 으로 서명해 실행 (개발용)
make app       # build/Paster.app (release) 빌드 + 서명
make install   # /Applications 로 복사 후 실행
make test      # swift test
make icon      # Resources/AppIcon.svg -> Resources/AppIcon.icns (아이콘을 바꿨을 때)
```

`make app` / `make run` 은 Sparkle 공개 키 파일(`Resources/sparkle-public-key.txt`, 저장소에 포함)이 필요합니다.

개발 빌드(`make run` 과 `VERSION` 을 지정하지 않은 `make app` / `make install`)에는 Sparkle 피드(`SUFeedURL`)가 없어 업데이트를 받지 않습니다. 정식 릴리스가 개발 빌드를 덮어쓰지 않게 하려는 것입니다. 설정의 "자동으로 업데이트 확인" 은 비활성화되고, `업데이트 확인…` 을 누르면 Sparkle 설정 오류가 보이는 것이 정상입니다. 업데이트를 받는 앱이 필요하면 Releases 의 zip 으로 설치하거나 `VERSION=x.y.z` 를 지정해 빌드하세요.

`make cert` 가 필요한 이유: ad-hoc 서명은 재빌드마다 서명이 달라져 손쉬운 사용 권한을 다시 요청하게 됩니다. 고정된 자체 서명 인증서로 서명하면 재빌드해도 권한이 유지됩니다. 마지막 단계에서 인증서를 코드서명용으로 신뢰하려고 macOS 가 로그인 암호를 묻습니다.

## 릴리스 (메인테이너용)

최초 1회, Sparkle EdDSA 키를 만듭니다 (개인 키는 로그인 키체인, 공개 키는 `Resources/sparkle-public-key.txt`).

```sh
make sparkle-keys
```

릴리스는 `main` 브랜치에서, 작업 트리가 깨끗하고 `origin/main` 과 같은 커밋일 때만 할 수 있습니다. 새 버전은 기존 최신 릴리스보다 높아야 합니다.

> **main 에는 merge commit 이나 fast-forward 로만 합치고, squash merge 는 하지 마세요.** 빌드 번호(`CFBundleVersion`)는 `git rev-list --count HEAD` 이고 Sparkle 은 이 값으로 업데이트 여부를 정합니다. squash 하면 커밋 수가 줄어 빌드 번호가 되돌아가므로, 이미 설치된 앱이 새 릴리스를 업데이트로 인식하지 못합니다.

```sh
make release VERSION=x.y.z DRY_RUN=1   # 1. 업로드 직전까지만 (결과물: build/release/)
make release VERSION=x.y.z             # 2. 요약을 보여 주고 y 입력 시 GitHub Release 업로드
```

빌드 · 서명 · zip · appcast 생성 후 GitHub Release 로 올립니다. 릴리스 노트는 `docs/release-notes/vX.Y.Z.md` 가 있으면 그것을 쓰고, 없으면 직전 태그 이후 커밋 제목을 씁니다.

`make release` 후 설치된 앱에서 업데이트를 확인하려면 3분쯤 기다리세요. GitHub 가 `releases/latest/download/appcast.xml` 리디렉션을 잠시(약 2~3분) 캐시해 두어, 그동안은 이전 릴리스의 `appcast.xml` 을 받아 "최신 버전입니다" 로 나올 수 있습니다.

> ⚠️ **반드시 백업하세요.**
> - "Paster Local Signing" 인증서: 키체인 접근에서 `.p12` 로 내보내기
> - Sparkle EdDSA 개인 키: `.build/artifacts/sparkle/Sparkle/bin/generate_keys -x <file>`
>
> 두 파일은 저장소 밖(예: 비밀번호 관리자)에 보관하세요. 둘 중 하나라도 잃으면 업데이트가 깨지고, 사용자의 손쉬운 사용 권한이 초기화됩니다.
